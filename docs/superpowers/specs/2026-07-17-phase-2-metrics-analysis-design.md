# Phase 2 统一指标与异常分析设计

## 1. 目标与边界

Phase 2 在 Phase 1 的标准化数据之上实现确定性的电商指标、三套基线对比、异常识别和报告数据。所有数值由 Pandas/SQL 层计算，LLM 只能在后续阶段选择工具和解释结果，不能修改公式。

本阶段不实现 FastAPI、Streamlit、NL2SQL、LangGraph 或真实平台 API。报告先输出可序列化的“图表数据 + 规则化文字建议”，后续界面直接消费同一结果。

## 2. 方案选择

采用“共享指标内核 + 按业务域拆分工具”的方案：公共层统一时间区间、金额精度、安全除法、可用性和配置；销售、流量、用户、广告、商品分别计算；异常工具只读取这些已计算指标。

没有采用把全部逻辑写进一个分析类的方案，因为它难以单独测试和复用；也没有采用只写数据库视图的方案，因为本项目必须支持文件导入后的 Pandas 分析与缺字段降级。

## 3. 数据契约升级

在不破坏 Phase 1 文件的前提下新增可选字段，并提供增量迁移：

- `payment_info`：`coupon_discount`、`promotion_discount`、`shipping_fee`，默认按 0 参与计算。
- `refund_info`：`refund_quantity`，用于退货率；缺失时只禁用退货率。
- `traffic_visit`：`device_id`，访客键优先使用账号 `user_id`，否则使用设备 `device_id`；两者都缺失时该行计入 PV，但不计入 UV。
- `ad_attribution`：`attribution_type`，仅接受 `direct` 或 `indirect`；缺失时按 `direct` 处理，兼容旧数据。

渠道只接受六类标准值：自然搜索、推荐、付费投放、直播、短视频、活动流量。工具按渠道独立分组，未知渠道进入数据质量提示，不能静默合并到其他渠道。

## 4. 统一指标口径

统计区间采用左闭右开 `[start, end)`，避免相邻周期重复计算。

- 成交 GMV：区间内所有下单订单的 `order_amount` 之和。
- 实际销售额：成功付款金额减优惠券、满减和运费，并剔除累计成功退款金额大于等于成功付款金额的全额退款订单。
- 退款金额：区间内退款成功记录的实际退款金额。
- 净销售额：实际销售额减退款金额。
- 店铺 UV：区间内访客键去重数；PV：访问记录数。
- 下单、付款、整体转化率分别为下单 UV/店铺 UV、付款 UV/下单 UV、付款 UV/店铺 UV。
- 客单价：实际销售额/有效付款订单数；件单价：实际销售额/付款商品件数；加购率：加购 UV/店铺 UV。
- 直接、间接、7 日 ROI、CTR、CPM、CPC 严格使用已确认公式。
- 退款率：有成功退款的订单数/成功付款订单数；退货率：成功退货件数/付款商品件数。
- 老客户：首次成功付款时间早于统计周期开始；复购率和新客占比按成交 UV 计算。

状态值在代码中使用小型白名单规范化。无法确认成功状态的数据不参与“成功付款/退款”类指标，并返回质量提示。任何分母为 0 的指标均返回“不可计算”及原因，不伪造为 0。

## 5. 基线与异常

所有指标共用三套比较：日环比（前一等长周期）、周同比（向前 7 天的等长周期）、月环比（向前 1 个自然月的对应周期）。变化率绝对值边界固定为：`[5%,15%)` 轻微、`[15%,30%]` 显著、`>30%` 严重，低于 5% 为正常；基线为 0 时不可计算。

连续日序列的业务异常使用 IQR 与 3 Sigma 两种证据。样本不足时不强行判异常；只有严重波动，或同时被 IQR/3 Sigma 支持的异常，进入“有价值的异常”列表。异常记录保留指标、日期、当前值、基线、幅度、等级和证据。

## 6. 缺表、缺字段与报告降级

每个指标声明依赖的表和列。缺失时只禁用该指标及相关图表，其他能力继续运行：缺 `traffic_visit` 时禁用 UV/PV/转化图；缺广告表时禁用 ROI；缺 `refund_quantity` 时仅禁用退货率。

报告结果包含：指标卡、可用图表序列、缺失依赖、数据质量提示、有价值异常和规则化建议。建议只引用已计算事实，例如“付款转化率严重下降，优先检查支付链路”，不让文本生成改变数值。

## 7. 测试与验收

使用小型 DataFrame 固定样例进行单元测试，覆盖金额精度、区间边界、严格去重、渠道拆分、成功状态、全额/部分退款、零分母、7 日归因、三套基线、阈值边界、缺字段降级和有价值异常筛选。最后运行 Python 3.13 全量回归；MySQL 迁移以 DDL 静态测试覆盖，真实 MySQL 仍需可用凭据后验收。

验收标准：同一输入在报表、异常和建议中得到相同指标值；缺失数据不会导致整个分析失败；LLM 相关代码中不存在业务公式。
